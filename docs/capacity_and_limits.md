## Power Apps row limit

The apps' data row limit is 2,000. The only collection that could approach it is the measures app's open work list. At this profile about **720** submissions are open at any time. The app only loads open submissions for periods that ended in the last 13 months (`period_end`), so values abandoned long ago can't push it over the limit. Admins can see those in the `expected_not_received` view in SharePoint.

Active measures (335), people (130) and teams are all well under the limit.

## Power Automate usage

Rough actions per day, averaged over a year:

| Flow | Actions a day |
|---|---:|
| Value entry and review (PMSSaveValue, PMSReview) | 3,024 |
| Expected submissions (PMSCreateExpected) | 103 |
| Reminders (PMSReminders) | 151 |
| Exports (PMSExportRun, PMSExportScheduler) | 1,431 |
| Wellbeing view (PMSWellbeingView) | 468 |
| **Total** | **5,177** |

Office Script runs: about 269 a day, against a limit of about 1,600 a day per account.

These figures are for year 5. The nightly full export grows with history: about 49,293 rows after one year and 237,389 after 5. If that ever becomes a problem, change EXP-FULL-NIGHTLY in `export_jobs` to weekly. That cuts its share by six sevenths, and nothing else needs to change.

Microsoft sets daily limits on Power Platform requests per licence, and changes them from time to time. At this profile the system uses roughly 5,177 actions a day. Some of these count against the person using the app and some against the flow owner, depending on how the flow is triggered. Check the current limits for your licences with IT. If the service account gets throttled (flows slow down rather than fail), the fix is a Power Automate Process licence for the busiest flows, not a redesign.
